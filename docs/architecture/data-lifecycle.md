# 数据、旧历史与恢复规格

日期：2026-11-03。依据 R7 与 SEC-07 用户确认；关联 CORE-06 / 07、SEC-06 / 07 / 08、WS-01 / 02、SESSION-02 / 06 / 09、OPS-04 / 05。产品规格；CORE-06 已实现受管索引、原生历史只读分页、独立检查点与中断恢复，范围及证据见[实施方案](implementation-plan.md#core-06-已交付边界)。SESSION-02 已验收视图恢复及旧 CLI 历史只读发现，见[逐项证据](../validation/session-02-evidence/acceptance.md)。数据迁移、旧历史续聊、备份及其他后续条目仍按各自阶段验收。

## 默认位置与修改

Windows 默认使用当前用户 `%LOCALAPPDATA%\PiWorkbench` 保存工作台数据库、工作台新建的 pi 原生会话、独立目录、快照与日志。项目代码继续位于原目录；既有 pi 提供商 / 模型配置沿用原来源，凭证不复制到业务库。启动时显示实际展开后的绝对路径，不写死用户名。M1 建立统一数据根目录配置，后续 M5 提供设置中的受控迁移；不能只改字段就宣称数据已经搬好。

SEC-06 已建立原生凭证边界：默认离线不读取真实配置，显式 PIW_PI_AGENT_DIR 仅将现有 pi 目录交给宿主读取状态、注册已知脱敏值；不执行凭证命令、不刷新 OAuth、不发模型请求。内部更新按原生锁、revision 和原子替换保留其他配置及原文件权限，浏览器写入仍关闭。原生配置不是新建的工作台加密库；本轮不迁移或重写用户真实配置。[实现与验收](implementation-plan.md#sec-06-已交付边界)明确限制。

历史 / 检查点保持原文，预览、全文、审批摘要、流式 / 重放、诊断与导出使用同一脱敏策略，展示副本不写回 SDK 或执行参数。损坏记录导出不再无条件返回原字节：UTF-8 安全解析且无命中时保留字节，命中时只返回标记过的脱敏副本，无效 UTF-8 / 未知二进制返回 422，原件留本机。内容过滤只覆盖已知值和常见格式，不能承诺任意会话内容或备份天然无秘密。

迁移先展示源 / 目标、分类大小、可用空间和影响。目标须为可写本地目录，避免源 / 目标互相嵌套及覆盖不相关数据。等待任务空闲、处理待审批 / 排队并关闭受管终端后，暂停所有工作台写入和历史导入；CLI 外部源不受迁移控制，仍只读。取得单实例 / 数据锁，再一致性复制 SQLite（包含 WAL 中已提交内容）、JSONL、inflight、账本、索引引用和独立目录。禁止仅复制主 db 文件或在写入时逐文件拼凑备份。

校验数据版本、内容完整性和相互引用；必要的管理路径通过可验证映射重绑定，不能任意改写原生历史或重写历史轮次的原始执行目录。宿主管理的独立目录迁移会影响未来实际 cwd，须明确预览并验证重绑定；尚不支持时阻止该迁移并说明原因。用户项目目录、外部旧历史与 pi 配置不移动。

成功后才原子切换启动位置并重新打开验证；稳定的启动定位配置留在默认应用目录。失败保持原位置可用，保留诊断及原数据，不自动删除唯一副本；旧数据清理由用户另行决定。重启不恢复旧授权或自动执行中断任务。相关崩溃 / 磁盘不足 / 路径失效 / 版本不兼容用例在 OPS-04 实际验收。

## 客户端授权与恢复

SEC-08 客户端授权与数据恢复相互独立：票据 120 秒一次性、客户端授权最长 8 小时，只留宿主内存；Cookie 为 HttpOnly / SameSite=Strict 会话 Cookie，浏览器存储不保存 bearer。服务重启、恢复备份或迁移后都不恢复旧 Cookie / 票据 / CSRF 对应的授权，桌面也须从新宿主取得身份。浏览器关闭不取消任务，撤销 / 到期只断开该客户端观察；重新配对后可继续只读查看既有历史。授权细节见[实施方案](implementation-plan.md#sec-08-本机客户端授权边界)。

## 资源信任记录与恢复

SEC-07 的资源信任记录使用独立 `resource_trust` 表，仅保存来源、实际目录、内容指纹、确认客户端 / 时间与撤销时间，不复制资源正文或密钥。按用户确认，重启可复用完全匹配的版本；每轮重新检查实际来源和字节，变化、消失、链接、超限或损坏记录不获得加载许可。执行审批与 SEC-08 客户端身份仍不恢复。迁移或恢复备份后，资源需重新核对实际目录 / 内容，不能仅因数据库存在记录就执行扩展或脚本；备份文件本身需按本机敏感数据保护。

撤销记录不删除原资源或历史。已开始轮次保留原快照，后续轮次使用新检查结果；SDK 原生历史可能保留当时的上下文及模型回复，撤销不意味着从历史中抹去该文本。当前没有原生扩展、脚本或包安装执行能力，信任记录不能启用它们。

## 工作区身份与恢复

WS-01 的独立 `workspaces` 表保存工作区 ID、物理目录指纹、规范化路径和目录默认名；WS-02 的 `0007_workspace_recents.sql` 显式迁移增加 `custom_name`、`last_opened_at`、`revision` 及最近索引。由 daemon 独占写入，不保存模型、授权、项目资源正文或活动选择。物理指纹来自平台 / 设备 / inode / 创建时间，实际路径经 realpath 解析，同目录别名在唯一索引约束下复用记录。当前选择与本窗口已打开列表仍属于客户端视图；最近记录与自定义名属于持久元数据。

只有成功显式打开 / 切换才更新最近时间，降序排列，同毫秒单调顺延、ID 升序兜底；校验、刷新、重命名与重新定位不更新时间。最多展示 100 项并返回总数，不删除更早登记；旧库没有可靠的最近时间，保持空值直到重新打开，内部 standalone 登记不加入最近。自定义名去首尾空白后 1–80 Unicode 码点，拒控制 / 格式字符；恢复默认名写 null。编辑以 ID / revision 做 CAS，失败不推进版本，冲突不自动覆盖。

从最近移除只将 `last_opened_at` 置空，保留身份、自定义名、目录、项目、会话及当前窗口，后台任务继续；重新打开恢复同一记录。重新定位只接受同一物理目录，先校验读写 / 清理能力，再以 revision 提交新路径和目录默认名，不改变最近时间。选择器只填路径，另行保存；拒绝把旧身份绑定到另一目录。项目绑定与既有会话 cwd 不随登记路径自动改写；旧 cwd 与登记路径不匹配时续发拒绝且不启动模型，SDK 历史和资源信任保留原来源。

打开及切换重新检查目录和访问能力，检查期间创建并删除一个独占的 4 字节探针。失败不改登记、不建会话；路径被另一目录替换时，校验旧身份失败，必须重新打开确认新目录。原记录与历史保留，不把旧会话或信任绑定到替换目录。打开目录不移动代码、不载入项目资源、不授予工具权限；恢复数据库也不恢复客户端授权。数据迁移和实际写入边界须按后续功能验收，不能将一次目录校验当作永久访问保证。

## 项目组织元数据

WS-06 的 `0008_project_organization.sql` 显式迁移在 `projects` 增加 `pinned`、`position`、`revision`、`removed` 和 `creation_input`，保留旧 ID / 名称 / 默认目录，按旧插入顺序初始化位置。项目名、置顶和组内顺序属于 daemon SQLite 持久元数据；检索 / 收折属于窗口视图，不保存消息体、凭证或授权。项目保存以 `remember:false` 复用工作区身份及读写校验，不更新最近打开时间。

创建请求绑定原始输入，即使项目以后改名也不能用同请求另建；移除保留墓碑，迟到重试不能复活项目。编辑及整理使用 revision，目录 IO 后再检查版本；保存失败不推进状态。项目默认目录仅用于未来会话，不改已保存配置、实际 cwd 或模型。未绑定目录的项目各会话分别保存独立执行空间。

解散项目时，ProjectService 与 SessionService 经 SessionStore 公开 detach 边界，在同一个 SQLite 事务内将所属会话 `project_id` 置空并保存项目墓碑；任一步失败全部回滚。提交 / 轮次、JSONL、检查点、文件、权限和资源信任均保留，已经准入的后台任务继续。发送在异步目录校验后重查归属，拒绝使用已移除项目或旧默认的迟到准入，不自动重放。任意会话主动移入 / 移出及环境迁移由 SESSION-13 单独验收。

## 受管会话的内核回收与冷恢复

SESSION-11 在 `session_configurations` 增加 `title_source` 与 `title_version`，0006 显式迁移将既有标题保留为 local / 1。人工改名以 `sessionId + expectedVersion` 执行 SQLite 单语句 CAS，成功转为 user 并递增版本；本地后台候选还必须匹配 `creationRequestId` 且当前来源仍为 local，不能覆盖任何人工标题。保存失败不推进版本，改名不改会话身份、cwd、组织 / 未读状态或原生 JSONL。

标题索引直接读取该权威表并统一脱敏，不另建可倒退的缓存表。已提交后发送独立标题通知，客户端以版本合并列表、编辑回执和首发 / 续发回执；断线补读 SQLite 最新索引，不重放改名命令。旧 CLI 历史继续只读，不创建标题记录或改写源文件；SESSION-12 基础搜索仅覆盖受管会话。

### SESSION-12 派生搜索索引

0009 创建 `session_search_documents`，daemon SearchService 独占写入已脱敏的用户 / 助手全文、字面匹配字段与原消息 ID；标题、项目、归档和运行状态仍从各自权威服务读取。每次搜索核对原生文件身份 / 纳秒时间、轮次 / 检查点及脱敏规则 revision；变化时重建该会话，读取前后来源不一致则拒绝混合版本。重启首次搜索重新验证并重建，不启动 SDK。会话从受管索引移除后清理派生记录；丢失 / 损坏历史清掉旧正文并返回不完整诊断，原件保留。

该表可丢弃重建，不写回 JSONL、检查点或模型上下文。搜索词仅在当前 Dialog 内存和请求中存在，不落普通日志或浏览器存储。正文按原消息 ID 读取所在历史页，过期目标显式报错，不静默定位另一消息。主动项目迁移 / 删除产品入口尚未交付，索引边界由明确 SQLite 夹具验证，不代表 SESSION-13 已验收。

SESSION-03 的 `session_organization` 独立保存 pinned / archived / manualUnread、resultVersion / readVersion、对应终态请求及 revision。它属于 daemon 的个人列表元数据，既不是消息副本，也不是执行或审批权威。0005 迁移保留既有提交与 JSONL，将迁移前已有终态的结果 / 阅读游标对齐；新中断恢复在同一事务中推进结果版本，重复终态不重复产生未读。

任务接受、终态写入与相关整理版本在各自 FULL SQLite 事务内提交；归档检查和提交接受相互复核。已读回执绑定已展示结果版本及整理修订号，旧回执返回冲突；恢复归档不创建 SDK、不改 cwd / 模型 / JSONL，也不恢复旧授权。应用重启后的整理状态可恢复，窗口草稿与阅读书签仍遵循 SESSION-02 的 sessionStorage 范围。

SESSION-01 增加 `projects`、`session_configurations` 和 `session_submissions`，迁移由 daemon 独占执行。首次提交在单个 SQLite FULL 事务中保存原 sessions 索引、稳定创建请求 / 首消息身份及配置，再启动 SDK；落库失败不留下空会话。提交正文是尚未交给原生历史的 outbox，匹配的 SDK user entry 可读后清空该列，已提交正文只读回源 JSONL。请求摘要和消息 / 轮次身份保留用于幂等；不能用删除记录解除请求绑定。

服务重启时仅按可核对的原生终态恢复已接收提交，其余标记中断；不因读取列表、重试同一 HTTP 请求或重新配对而调度模型。明确重试只针对已知失败，使用新请求 / 轮次并引用原任务；原会话、原消息和历史保留，结果未知不提供原任务重放。独立目录持久保留，数据根下的 standalone 不能通过链接重定向到外部。客户端草稿及未确认请求只属于当前窗口的 sessionStorage，和 SQLite 权威输入、SDK JSONL、授权 Cookie 分开；刷新可恢复，应用重启后的草稿恢复不在本次验收范围。

SESSION-02 将每窗口的小型视图书签与草稿分开：面板、分页 cursor、展开 ID、所选变更引用、消息锚点 / 偏移与跟随状态仅写 sessionStorage；不复制消息体、执行状态或授权。MRU 最多 3 个挂载视图含新草稿，淘汰只断开所属订阅和清理查询；后台 SDK 由 daemon 持有，重开 / 重连不重复发送，迟到结果不能换当前面板。刷新可恢复小型状态，整个应用重启 / 跨窗口同步未在本次交付。

CORE-07 的空闲回收只释放 SDK 进程，不删除原生历史或检查点。下一次显式打开时，仅对 daemon 独占数据目录中已经登记的受管会话校验来源、路径、cwd、原生身份和 v3 版本，再由 SDK 重开同一 JSONL，不复制整份文件。进程 epoch / PID 更新，原生会话身份与既有消息 ID 保持稳定；多代际索引不重复展示消息，旧中断检查点保留原位置。

独立 inflight 仍只供展示，未确认输入与部分回复均不导入模型上下文。冷恢复自身不调用模型；后续必须有显式任务才发送新输入，不恢复旧授权或自动重发等待队列。损坏 / 不支持的来源保留原件并阻止恢复。该能力不接管旧 CLI 会话；实际实现与来源见 [CORE-07 验收](implementation-plan.md#core-07-已交付边界)。

## 旧 pi 历史

M2 首版发现并只读展示现有 pi 历史，区别于工作台管理的新会话。显示来源、时间、原执行目录及“只读”状态；打开不创建 SDK 运行时，不追加消息、不重命名 / 移动 / 归档 / 删除源 JSONL，不恢复源授权。只读样本不能调用模型。

SESSION-02 只从显式 `PIW_PI_AGENT_DIR/sessions` 发现 SDK 的 `sessions/<cwd>/*.jsonl` 及直接 JSONL；未指定不猜用户默认目录。SEC-08 仅允许 desktop 身份，来源 / 消息统一 SEC-06 脱敏。最多 2000 目录项 / 200 文件、每文件 16 MiB、首行 64 KiB；拒绝链接，仅支持 v3，v1 / v2 明示不兼容且不迁移。Opaque ID 由已发现相对路径摘要产生，客户端不能提交任意文件路径；打开不调用 SDK SessionManager 或写索引 / 授权。

CLI 可能继续写入源文件，读取核对目录 / descriptor 与文件 dev / ino / 大小 / 修改时间的稳定快照，以身份及内容摘要绑定 100 消息分页与全文；变化返回 409，拒绝混合快照。单条 UTF-8 预览 64 KiB，只读最新叶子分支；不完整末行留待刷新，不当作有效消息写回源文件。损坏或不兼容时显示原因，保留可读取内容与原始源位置，不修复原件。工作台索引为派生数据，来源失效时可诊断。

原地续聊后续由 SESSION-06 的受保护接管流程交付：必须先验证 CLI 并发写入、租约 / 锁、版本冲突和 SDK 兼容，不把复制文件或改索引当作安全续写。具体直接接管或复制后继续的选择在进入该阶段前再确认；首版不开放“发送到旧历史”。

## 备份与恢复

用户选择仅升级前自动备份，其余手动；不启动每日备份，不预设最近 7 份轮转。备份列表与删除影响可查看；保留数量、日志上限和磁盘清理在相应阶段再确认。普通会话及未审查所需快照不自动删除。

手动备份可选择其他磁盘，先检查任务 / 写入状态、一致性和目标空间，再保存版本清单、数据库、管理的 JSONL / 检查点、账本及其引用、独立目录内必要产物和可迁移的非密钥设置。用户项目代码与外部只读历史不被默认为完整备份，界面列出不包含项与源路径关系。提供商凭证文件 / 模型密钥不进入备份；会话内容仍可能包含用户输入的敏感信息，不宣称备份天然无敏感内容。

升级前备份失败或无法验证时暂停升级，保留当前版本并给出恢复方式；不静默跳过。恢复先校验版本与完整性、预览替换对象，再保护当前数据后切换；失败回退原数据。不能恢复有效授权、自动重放任务或覆盖用户项目。文件 / Diff 与快照重新关联需实际测试。M5 OPS-05 / 04 验收，当前原型仅展示流程。

## WS-03 Git 观察数据

Git 根、Git 目录、HEAD、子模块主仓库及检查时间均为本地只读观察，不新增数据库迁移或持久分支缓存；应用重启从登记身份与会话 cwd 重新检查。读取不改变工作区最近时间／revision、仓库 index／HEAD／reflog、pi 配置或授权。执行身份继续属于 daemon，Git 显示失败不改变已保存会话与 SDK 历史。

## SESSION-07 独立目录来源

0010_session_spaces增加session_origins和session_configurations.membership_version。首次接受输入时在同一SQLite事务保存原始目录/工作区/项目/时间（created）；旧记录回填为legacy-observed，只代表迁移时观察。仅组织归属及解散分组递增membership_version，不改来源行、实际cwd、历史、文件或已接受请求摘要。独立目录不是临时缓存，退出不删除。后续实际环境切换必须保留各执行段/产物的原来源。

会话空间只读检查先后复用WorkspaceService物理身份校验，无探针、最近顺序写入或SDK准入；目录替换或检查中归属变化拒绝混合响应。TrustService只检查当前cwd/显式全局来源，精确指纹和cwd绑定的信任不跨项目继承；返回资源元数据而非正文，统一SEC-06脱敏。配对desktop专用接口沿用Host/Origin/CSRF与协议边界。

## WS-07 目录不可用与信任身份

工作区不可用不删除 SQLite 会话、草稿或 SDK JSONL，不改 cwd 或归属。daemon 对已接受任务持续采样原目录身份与可读性；未发送的队列任务取消并可明确重试，已发送任务中断，保留现场，检查恢复与重启都不自动重放。结束后释放无效目录的 SDK 进程，历史观察继续可读。

同物理目录重新定位沿用 revision CAS，不传递既有会话 cwd／信任；恢复原路径并明确检查后才能在旧会话继续，实际环境迁移留待 SESSION-13。删除后另建同名目录不匹配原物理身份；打开它只可得到新工作区，不将旧会话重新绑定。资源信任的内容指纹加入项目／来源目录物理身份；旧路径格式的记录保留审计但不自动匹配，需要重新确认，不写用户 pi 配置。

## SEC-09 追加审计

operation_audit不保存凭证或原生消息正文，写入及读取均统一脱敏；旧秘密后来被识别时只在展示／导出再次过滤，不改写旧行。原件不自动清理、不提供删除API；仅导出固定快照的当前筛选页，下载副本由用户单独管理。普通UPDATE／DELETE由SQLite触发器拒绝，宿主业务创建权限需审计同事务成功，撤销失败不复活权限。功能启用前记录保留在原会话历史，不伪造补录。

## WS-04 目录轮次观察

0014_directory_rounds 由 daemon 独占，保存 turn／session、私有物理身份／cwd、实际 SDK PID、占用状态和脱敏观察 JSON；不保存文件正文或恢复版本。轮次前／每秒／收尾有界元数据采样最多保留 32 个变化路径，覆盖受限或不可用明确记录；不跟随链接。遍历未完成不能据文件缺失断言删除，元数据一致也不能证明没有外部编辑。所有观察固定来源不确定、automaticRollback=false，不自动清理。

最终观察持久成功且 SDK prompt 落稳或实际子进程退出后才释放；保存失败保持隔离。重启把未结束记录转为中断；旧 PID 仍存活则仅保留阻塞隔离，既不接管／杀死不明进程，也不恢复授权或任务。PID 复用可能延长保守隔离。文件版本和工具来源分别由 CHANGE-01／02 扩展，恢复写入仍待后续 CHANGE 功能。

## CHANGE-01 文件版本所有权

轮次前后原始文件版本属于 daemon 数据根下独立 Git 账本；SQLite 保存身份、阶段状态、不可变引用和脱敏诊断，不复制文件正文。版本引用只有账本对象和清单成功保存后才记 ready；中途失败保留已经产生的对象供诊断，不自动 GC 或删除未审查版本。基线、收尾、失败与中断分开保存，重启只标中断，不拿当前目录补造历史收尾或恢复授权。

收尾必须等 WS-04 的实际落稳／进程退出证明，元数据持久失败继续隔离。文件字节不含 ACL／权限／空目录承诺，排除范围和未知来源明确保留；读取清单或文件版本校验摘要，损坏不回落到当前文件。CHANGE-01 不开放恢复、Diff 或自动回滚接口，不改用户 Git 历史，后续 CHANGE 分别验收。

## CHANGE-02／03 工具来源与历史审查

0016_change_tool_observations 由 daemon 保存最终守卫的调用身份、参数摘要、观察字节摘要与完成状态，每轮最多 128 项；不复制参数原文或文件正文，也不保存许可。SDK 实际 execute 结束后等待宿主完成观察握手，再进入后续工具或轮次收尾。未完成记录在重启时标为中断，不补造末态或恢复执行。旧版本和观察记录不自动清理。

来源由同一轮不可变基线／收尾与工具观察链推导；完整一致仅称“工具观察一致”，缺失区段或外部编辑标为混合／未知。命令、排除项和不完整观察不构成独占归属，automaticRollback 始终 false。已保存的历史不因今天文件变化而改写。

只读文件列表／Diff 只读取清单与对象均验证的独立账本版本，文件树必须与清单完全一致；损坏返回不可用，不读取当前 cwd 补齐。配对 desktop 请求绑定 session／turn／不透明 file ID。每页最多 100 项；二进制／非 UTF-8 不造行数，超过 256 KiB 或 4000 行不展示截断补丁。展示按完整文件脱敏，多行脱敏改变行结构时隐藏预览以保留真实行号。无接受、删除版本、恢复或回滚写入口。

## CHANGE-05 回滚操作日志

0017 的 change_rollbacks 保存操作身份、所属物理目录／历史轮次、当前及目标摘要、操作前后独立账本引用、逐路径进展、来源和结果。原始字节仅保存在账本，SQLite 展示字段统一脱敏，私有身份列不经客户端。确认票据不持久化；进程重启将 prepared／running 标中断，不恢复执行或补偿。结果和审计在释放目录之前保存，写入失败保留隔离。历史 baseline／final 及 SDK JSONL 不修改，不删除未审查版本。
### 回滚事实与上下文（CHANGE-09）

`change_rollbacks` 持久意图、单独覆盖来源、前后不可变引用、逐文件现场哈希、失败/条件补偿/中断状态。操作后引用带独立 snapshotId，补偿后现场与先前尝试引用分开；无法采集则明确 unavailable。服务恢复只把 prepared/running 标中断，内存确认永不恢复。分页事实用于桌面查询及下次同物理目录执行的有界环境说明，不撤销 SDK 消息历史，不产生额外模型请求。

### CHANGE-04 接受决定

0018 的 `change_decisions` 只由 daemon 插入，唯一键为历史 turn／file；保存 session、原 baseline／final、人工来源、actor 和时间，不含工作文件正文或许可。重复接受返回同一决定，和审计在同一事务内落盘。无更新／删除业务入口，不因后轮改动、回滚或重启丢失。全轮处理进度从已验证历史成员与接受／成功回滚事实的并集实时推导，不持久化可漂移的客户端计数；当前可用性由 CHANGE-07 独立核对。
