# 数据、旧历史与恢复规格

日期：2026-11-02。依据 R7 与 SEC-07 用户确认；关联 CORE-06 / 07、SEC-06 / 07 / 08、WS-01 / 02、SESSION-02 / 06 / 09、OPS-04 / 05。产品规格；CORE-06 已实现受管索引、原生历史只读分页、独立检查点与中断恢复，范围及证据见[实施方案](implementation-plan.md#core-06-已交付边界)。数据迁移、旧 CLI 历史发现、备份及其他后续条目仍按各自阶段验收。

## 默认位置与修改

Windows 默认使用当前用户 `%LOCALAPPDATA%\PiWorkbench` 保存工作台数据库、工作台新建的 pi 原生会话、独立目录、快照与日志。项目代码继续位于原目录；既有 pi 提供商 / 模型配置沿用原来源，凭证不复制到业务库。启动时显示实际展开后的绝对路径，不写死用户名。M1 建立统一数据根目录配置，后续 M5 提供设置中的受控迁移；不能只改字段就宣称数据已经搬好。

SEC-06 已建立原生凭证边界：默认离线不读取真实配置，显式 PIW_PI_AGENT_DIR 仅将现有 pi 目录交给宿主读取状态、注册已知脱敏值；不执行凭证命令、不刷新 OAuth、不发模型请求。内部更新按原生锁、revision 和原子替换保留其他配置及原文件权限，浏览器写入仍关闭。原生配置不是新建的工作台加密库；本轮不迁移或重写用户真实配置。[实现与验收](implementation-plan.md#sec-06-已交付边界)明确限制。

历史 / 检查点保持原文，预览、全文、审批摘要、流式 / 重放、诊断与导出使用同一脱敏策略，展示副本不写回 SDK 或执行参数。损坏记录导出不再无条件返回原字节：UTF-8 安全解析且无命中时保留字节，命中时只返回标记过的脱敏副本，无效 UTF-8 / 未知二进制返回 422，原件留本机。内容过滤只覆盖已知值和常见格式，不能承诺任意会话内容或备份天然无秘密。

迁移先展示源 / 目标、分类大小、可用空间和影响。目标须为可写本地目录，避免源 / 目标互相嵌套及覆盖不相关数据。等待任务空闲、处理待审批 / 排队并关闭受管终端后，暂停所有工作台写入和历史导入；CLI 外部源不受迁移控制，仍只读。取得单实例 / 数据锁，再一致性复制 SQLite（包含 WAL 中已提交内容）、JSONL、inflight、账本、索引引用和独立目录。禁止仅复制主 db 文件或在写入时逐文件拼凑备份。

校验数据版本、内容完整性和相互引用；必要的管理路径通过可验证映射重绑定，不能任意改写原生历史或重写历史轮次的原始执行目录。宿主管理的独立目录迁移会影响未来实际 cwd，须明确预览并验证重绑定；尚不支持时阻止该迁移并说明原因。用户项目目录、外部旧历史与 pi 配置不移动。

成功后才原子切换启动位置并重新打开验证；稳定的启动定位配置留在默认应用目录。失败保持原位置可用，保留诊断及原数据，不自动删除唯一副本；旧数据清理由用户另行决定。重启不恢复旧授权或自动执行中断任务。相关崩溃 / 磁盘不足 / 路径失效 / 版本不兼容用例在 OPS-04 实际验收。

## 客户端授权与恢复

SEC-08 客户端授权与数据恢复相互独立：票据 120 秒一次性、客户端授权最长 8 小时，只留宿主内存；Cookie 为 HttpOnly / SameSite=Strict 会话 Cookie，浏览器存储不保存 bearer。服务重启、恢复备份或迁移后都不恢复旧 Cookie / 票据 / CSRF 对应的授权，桌面也须从新宿主取得身份。浏览器关闭不取消任务，撤销 / 到期只断开该客户端观察；重新配对后可继续只读查看既有历史。授权细节见[实施方案](implementation-plan.md#sec-08-本机客户端授权边界)。

## 资源信任记录与恢复

SEC-07 的资源信任记录使用独立 `resource_trust` 表，仅保存来源、实际目录、内容指纹、确认客户端 / 时间与撤销时间，不复制资源正文或密钥。按用户确认，重启可复用完全匹配的版本；每轮重新检查实际来源和字节，变化、消失、链接、超限或损坏记录不获得加载许可。执行审批与 SEC-08 客户端身份仍不恢复。迁移或恢复备份后，资源需重新核对实际目录 / 内容，不能仅因数据库存在记录就执行扩展或脚本；备份文件本身需按本机敏感数据保护。

撤销记录不删除原资源或历史。已开始轮次保留原快照，后续轮次使用新检查结果；SDK 原生历史可能保留当时的上下文及模型回复，撤销不意味着从历史中抹去该文本。当前没有原生扩展、脚本或包安装执行能力，信任记录不能启用它们。

## 工作区身份与恢复

WS-01 的独立 `workspaces` 表仅保存工作区 ID、物理目录指纹、规范化路径和目录显示名；由 daemon 校验后登记，不保存模型、授权、项目资源正文或活动选择。物理指纹来自平台 / 设备 / inode / 创建时间，实际路径经 realpath 解析，同目录别名在唯一索引约束下复用记录。重启后显式重新打开同目录可复用身份；当前选择与已打开列表仅属于本窗口，不冒充 WS-02 的持久最近列表或重命名能力。

打开及切换重新检查目录和访问能力，检查期间创建并删除一个独占的 4 字节探针。失败不改登记、不建会话；路径被另一目录替换时，校验旧身份失败，必须重新打开确认新目录。原记录与历史保留，不把旧会话或信任绑定到替换目录。打开目录不移动代码、不载入项目资源、不授予工具权限；恢复数据库也不恢复客户端授权。后续工作区重新定位、数据迁移和实际会话 / 写入边界须独立验收，不能将一次目录校验当作永久访问保证。

## 受管会话的内核回收与冷恢复

SESSION-01 增加 `projects`、`session_configurations` 和 `session_submissions`，迁移由 daemon 独占执行。首次提交在单个 SQLite FULL 事务中保存原 sessions 索引、稳定创建请求 / 首消息身份及配置，再启动 SDK；落库失败不留下空会话。提交正文是尚未交给原生历史的 outbox，匹配的 SDK user entry 可读后清空该列，已提交正文只读回源 JSONL。请求摘要和消息 / 轮次身份保留用于幂等；不能用删除记录解除请求绑定。

服务重启时仅按可核对的原生终态恢复已接收提交，其余标记中断；不因读取列表、重试同一 HTTP 请求或重新配对而调度模型。明确重试只针对已知失败，使用新请求 / 轮次并引用原任务；原会话、原消息和历史保留，结果未知不提供原任务重放。独立目录持久保留，数据根下的 standalone 不能通过链接重定向到外部。客户端草稿及未确认请求只属于当前窗口的 sessionStorage，和 SQLite 权威输入、SDK JSONL、授权 Cookie 分开；刷新可恢复，应用重启后的草稿恢复不在本次验收范围。

CORE-07 的空闲回收只释放 SDK 进程，不删除原生历史或检查点。下一次显式打开时，仅对 daemon 独占数据目录中已经登记的受管会话校验来源、路径、cwd、原生身份和 v3 版本，再由 SDK 重开同一 JSONL，不复制整份文件。进程 epoch / PID 更新，原生会话身份与既有消息 ID 保持稳定；多代际索引不重复展示消息，旧中断检查点保留原位置。

独立 inflight 仍只供展示，未确认输入与部分回复均不导入模型上下文。冷恢复自身不调用模型；后续必须有显式任务才发送新输入，不恢复旧授权或自动重发等待队列。损坏 / 不支持的来源保留原件并阻止恢复。该能力不接管旧 CLI 会话；实际实现与来源见 [CORE-07 验收](implementation-plan.md#core-07-已交付边界)。

## 旧 pi 历史

M2 首版发现并只读展示现有 pi 历史，区别于工作台管理的新会话。显示来源、时间、原执行目录及“只读”状态；打开不创建 SDK 运行时，不追加消息、不重命名 / 移动 / 归档 / 删除源 JSONL，不恢复源授权。只读样本不能调用模型。

CLI 可能继续写入源文件，读取使用稳定边界并检查版本 / 大小变化；不完整末行留待刷新，不当作有效消息写回源文件。损坏或不兼容时显示原因，保留可读取内容与原始源位置，不修复原件。工作台索引为派生数据，来源失效时可诊断。

原地续聊后续由 SESSION-06 的受保护接管流程交付：必须先验证 CLI 并发写入、租约 / 锁、版本冲突和 SDK 兼容，不把复制文件或改索引当作安全续写。具体直接接管或复制后继续的选择在进入该阶段前再确认；首版不开放“发送到旧历史”。

## 备份与恢复

用户选择仅升级前自动备份，其余手动；不启动每日备份，不预设最近 7 份轮转。备份列表与删除影响可查看；保留数量、日志上限和磁盘清理在相应阶段再确认。普通会话及未审查所需快照不自动删除。

手动备份可选择其他磁盘，先检查任务 / 写入状态、一致性和目标空间，再保存版本清单、数据库、管理的 JSONL / 检查点、账本及其引用、独立目录内必要产物和可迁移的非密钥设置。用户项目代码与外部只读历史不被默认为完整备份，界面列出不包含项与源路径关系。提供商凭证文件 / 模型密钥不进入备份；会话内容仍可能包含用户输入的敏感信息，不宣称备份天然无敏感内容。

升级前备份失败或无法验证时暂停升级，保留当前版本并给出恢复方式；不静默跳过。恢复先校验版本与完整性、预览替换对象，再保护当前数据后切换；失败回退原数据。不能恢复有效授权、自动重放任务或覆盖用户项目。文件 / Diff 与快照重新关联需实际测试。M5 OPS-05 / 04 验收，当前原型仅展示流程。
