# 开发真实验收预算

日期：2026-11-01。关联 OPS-01、CORE、MODEL；依据共同确认 R6-02。此政策约束本项目的开发验收，不是产品正常使用的额度。通用产品预算仍按 M7 验收。

- 日常开发、UI 与可重复回归离线运行。必要真实验收沿用现有唯一提供商和模型；每个里程碑新增最多 2 次底层请求，单次请求输出上限 512 token，失败不自动重试。不额外调用模型生成标题、摘要或审查。
- 一次用户消息可能产生多次提供商请求。工具循环的下一回合、模型压缩、重试均分别计数；失败、中止及已经预占但结果不确定的请求也计入。手动重试仍受剩余额度约束。离线夹具不计费、不占真实额度，来源须标明。
- 请求前在 [JSON 记录](live-validation-budget.json)对应里程碑持久预占，记录唯一请求 ID、用途、输出限制、来源、状态与证据位置；预占后才能发出。完成后补结果与实际用量，缺失时保留未知。计数不可通过重新运行、删记录、重建文件、切分测试批次或跨里程碑借额度重置。
- 2 次限额是里程碑累计新增上限，不是每轮聊天、每个功能或每次运行各有 2 次。后续 M8 候选是否立项须另行确认，预算不构成立项授权。已验收 M0 不再重跑；原 3 + 1 次预算文件独立保留，不追溯改写。
- OPS-01 正式接入前要验证拦截点能覆盖 SDK 隐式回合、重试、压缩，能在并发时原子预占，并向所用提供商传递有效输出上限。若某路径不能可靠限制请求或输出，先使用明确标注的离线样本，不发该路径的真实请求。仅添加本政策和 JSON 不代表自动守卫已实现。
- 价格未配置、思考 token 的限制语义不明、错误 / 中止用量不完整时，费用或用量显示未知，不以输出限制承诺人民币总额。测试输入使用最小必要内容，不发送项目全量上下文或真实凭证；关闭工具自动循环和自动重试，以已验证的拦截点为准。
- 用尽后继续离线工作；确有不可替代的验收需要时，说明具体证据缺口和追加上限后再请求用户决定。本轮新增请求为 0。

## OPS-01 实测状态

`packages/agent-adapter/src/validation-budget.ts` 已实现跨进程文件锁、持久预占、512 token 输入边界和累计限额；离线测试验证失败 / 中止保留计数、缺文件拒绝、修改限额拒绝，以及 5 个独立进程只有 2 个预占成功。测试只使用临时副本，不写 canonical 预算记录。

真实提供商路径仍关闭（daemon 仅有只读假内核接口，PIW_KERNEL=real 拒绝）。这里的 token 检查只是预占入口校验，尚未证明 SDK / 提供商实际限制生效。后续真实传输必须覆盖隐式工具回合、压缩、重试与输出上限，再开放该路径；不能把本次算法验收等同于完整传输守卫。来源、命令与结果见 [OPS-01 验收](ops-01-acceptance.md)。SDK 冒烟只创建 / dispose，不发送 prompt。

旧证据：[原 3 次预算](m0-evidence/live-budget.json)与[补充 1 次预算](m0-evidence/live-abort-budget.json)累计 4 次，成本字段为未知。它们从本机 spikes 按原始字节归档，canonical 账本仅更新历史文件引用；计数、限额、预占记录和关闭状态不变，不因文件迁移重置预算。
