## CORE-01

真实 pi SDK 1.4.0 配合本地 HTTP SSE 夹具验证 9 类场景，另有 9 项 Node 边界测试。覆盖流式、错误、重试、steer / follow-up、中止、压缩及恢复。普通 agent_end 不表示稳定空闲，必须等待 agent_settled；手动压缩按独立操作完成边界处理。

原提供商的短回复、手动压缩及补充中止有真实调用证据。首次中止验证只有思考增量后上游异常断流，没有满足原取消条件，不能算作成功中止；后续补充在首个输出后中止并确认 SDK settled。累计真实模型请求为 4 次，费用未知，不重新执行这些调用。

## CORE-02

28 个真实 SDK 本地场景验证内建 / 扩展 / MCP / 嵌套工具、实际文件 / 命令 / HTTP 副作用、IPC 故障、拒绝与撤销。模型回复和审批裁决来自本地合成夹具，不是新增真实提供商调用。

tool_execution_start 在 tool_call 前发生，只表示准备调用。普通前置审批可能被后续扩展改参绕过；宿主须统一包装最终执行入口，批准并执行同一不可变参数快照。缺观察、断线、异常、失配、失效和未知调用均须在副作用前阻断。该结论不代表生产审批 UI、权限服务或操作系统沙箱已完成。

## CORE-03

34 个实际文件 / 独立 Git 账本 / SDK 文件工具场景验证脏内容保留、单文件 / 整轮回滚、外部编辑归属、同目录锁、路径限制及故障。历史验收器检查 54 个文件状态、58 个用户 Git 元数据文件、54 个快照和 185 次 Git 对象读取 / 哈希；37 次工具操作具有持锁与基线顺序证据。

unknown / mixed 来源不可自动整轮回滚。冲突先预检，运行失败逆序条件补偿，补偿遇外部编辑保留现场。大于 5 MiB、忽略 / 排除项、链接与外部副作用不构成可回滚承诺。文件 symlink 在原机器返回 EPERM，不能算作实际验证；目录 junction / hardlink 有测试。多文件操作不是 OS 事务，竞态、断电、其他平台和生产 M3 回滚须独立验收。

## 版本库与复核范围

`spikes/` 是本机早期实验目录，整个目录不提交。版本库仅保留上述小型历史报告 / 预算及当前 CI 使用的 [14 份固定契约录制](../../packages/agent-adapter/test/contracts/recordings.json)。录制位于同目录的 recordings/，原始字节与 SHA-256 不变，来源明确区分真实提供商和本地夹具。当前只读回归使用 pnpm test:contracts，无需 spikes、用户凭证或模型调用。

完整 M0 现场验收器依赖本机原实验源码、文件 / Git / 会话现场；仓库中的精简归档不声称具备这些完整现场。历史日志中的 spikes 命令仅作当时执行记录，不是克隆后的标准开发命令。生产实现与当前回归门禁见 [实施方案](../architecture/implementation-plan.md)及[工具规范](../development/tooling.md)。
