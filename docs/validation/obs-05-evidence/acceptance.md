# OBS-05 消息检索、引用与深链接

## 运行规则与验收方案

前置 OBS-01、FILE-02 已核对为 verified；INPUT-03 已独立提交。复用 SESSION-12 脱敏 SQLite 派生索引、CORE-06 SDK JSONL、稳定会话／轮次／消息／工具身份、FILE-02 当前文件读取和本窗口草稿。不新增模型请求或第二套历史权威。

- 默认会话搜索保持兼容；逐条消息模式可查当前或全部会话，分页按稳定身份返回每个正文命中。搜索过滤归档，直接链接可只读访问归档记录并明确说明。
- 链接仅含会话与持久对象 ID。daemon 每次重新核对归属；用户／助手实时视图通过轮次与角色解析原生消息，未持久保存的观察不可引用；持久中断检查点继续显示其来源与未确认送达状态。工具链接同时绑定轮次和调用，不把同名调用或 UI reply ID 当作原生身份。
- 引用明确加入所属输入、不自动发送，不撤销／改写历史。引用为当前显示的脱敏历史文本，最多前 4000 Unicode 字符，超长有截断说明；输入总上限仍为 16000。异步操作绑定草稿对象与视图代际，切换、卸载、编辑或待提交时不混入其他输入。归档只读，不能引用到已归档会话的输入。
- 代码复制只写入 Markdown AST 的代码源文本，不从包含行号、标题、按钮的 DOM 提取。Windows 剪贴板读回可规范为 CRLF，这与 INPUT-03 原始引用字节存储分开；剪贴板失败有恢复提示。
- 链接只在当前应用同源根路径内识别；拒绝附加参数、重复身份、未知协议和跨源特权跳转。打开链接不启动内核、不发送、不恢复授权；需要原有配对身份。
- 不可用的消息／工具返回真实诊断，不退到另一条记录。历史链接与当前文件明确区分：FILE-02 仍只读重验当前文件，外部变化隐藏过期内容；历史 Diff／消息不替换为当前文件。

验证使用实际 SQLite、合成且明确标记的 SDK 格式历史／工具观察和实际 SDK 本地夹具；分别记录。服务覆盖多命中分页、目标归属、归档、记录丢失与重启。Electron 覆盖代码精确复制、引用草稿竞态、跨会话／工具定位、分页与三视图淘汰、明暗窄窗、故障恢复。完成开发和命令行检查后执行完整 CI 窗口阶段及 Windows 原生验收；同 data/profile 重启、后台任务和正常退出单列证据。真实提供商请求 0。
