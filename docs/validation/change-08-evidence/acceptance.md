## 运行规则与实现

审批和历史详情共用 daemon 的范围观察，区分普通文件字节可保护、部分范围及不可回滚。范围不是来源证明、当前冲突判断或执行许可；混合／未知来源仍须产品内单独明确确认覆盖。写入前观察不保证未来收尾成功，原有逐次不可回滚确认不变。

沿用单文件 5 MiB、单阶段 32 MiB、2048 项、8 层边界；限额内普通二进制保存原始字节，Diff 能力另行判断。忽略项、链接／硬链接、私密配置、嵌套仓库、外部路径、ACL、空目录和命令外部副作用不受保护。大文件使基线失败时暂停写入；取消不产生文件写入。

每物理目录初始工程容量为 512 MiB，按 Git 对象磁盘 KiB 估算，80% 预警。采集发布前核对当前用量和保守预计新增；未知或不足即暂停采集，保存失败记录，不删除旧版本。此估算不承诺操作系统剩余空间或后续外部占盘不变。开发宿主可在隔离夹具降低容量；没有 renderer／用户配置入口。

所有已发布 refs 和必要对象保留，所有宿主 Git 命令关闭自动 GC／maintenance；没有过期、回收或删除入口。接受、归档、视图切换与重启不解除保留。引用缺失／被改／对象损坏产生当前失效诊断并禁用回滚，不抹掉原版本元数据、接受决定或审计，不读取当前工作文件冒充历史。

预检后的缓存不能成为使用失效版本的许可。实际执行在 WS-04 物理目录租约内、新采集和写文件前重新核对原 baseline／final refs；失效则持久记录冲突、整批零写并释放占用。回滚操作前版本同样受容量限制。客户端已知范围失效、查询失败或同步中时禁用预检及确认，取消仍可用。复用独立账本、SQLite 和顺序收尾生命周期。
