## 构建前的设计方案

颜色使用同一中性灰语义体系：暗色画布 #202020、侧栏 #181818、浮层 #2b2b2b、边界 #3b3b3b、正文 #ededeb、次要文字 #aaa9a5；亮色对应 #fafaf8、#efefec、#ffffff、#d7d7d1、#262723、#62635c。成功 / 新增和警告 / 等待使用专门语义色，不使用品牌亮色占据工作区。

Segoe UI Variable / Segoe UI / Microsoft YaHei 用于界面与中文；Cascadia Code / Consolas 用于路径与代码。正文 14 px、消息 15 px、次要文字 12 px、新会话标题 28 px，行高 1.6–1.8。代码区允许内部滚动，整页不横向溢出。

两方向使用完全相同的登录修复任务、目录、文件与场景，避免内容差异影响选择。侧栏 248 px；主阅读区左对齐、最大约 780 px；输入固定于当前对话区底部。两方向均不永久占用右侧面板。

```text
A 对话优先：侧栏 | 舒展的消息 + 内联工具步骤 | 按需轻量 Diff（440）
B 审查聚焦：侧栏 | 消息 + 轮次过程摘要       | 按需审查工作区（640）
```

A 把工具过程接在对应回复里，Diff 一次显示一个文件，保留更多对话宽度。B 把过程收为可展开轮次摘要，打开审查时给文件列表、Diff 与逐文件决定更多空间。用户已确认组合：A 作为日常基础，展开审查时使用 B；字号保留当前基线。评审入口现以组合为默认，A / B 继续保留作比较。

原则：信息围绕当前任务组织；工具细节按需出现；运行结果、审批与审查决定分别表达；主要动作仅突出一个；没有装饰性图表、渐变、营销卡片或虚构模型品牌。评审控制与模拟来源放在产品之外的评审栏。

构建前自查：用户已明确选择 Codex 式中性风格，因此保留系统字体和中性灰，特色放在对话 / 审查的空间切换，而不另加视觉品牌。两稿共用语义与内容，通过工具过程及审查布局形成可比较差异。沿用现有设计体系；此前技能检索未找到适配工作台的方案，未采用其 FAQ / 平滑锚点结果。本轮以用户 brief、既有体系和通用键盘 / 对比 / 减弱动效准则为依据。
