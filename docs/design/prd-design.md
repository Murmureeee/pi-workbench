# 交互式 PRD v2 的整体设计

依据当前 backlog 的 19 个模块、146 项需求整体重设计。采用 Codex 的项目 / 会话与审查工作流，吸收 Claude Code 的任务模式、上下文入口、折叠工具、按需面板和后台任务：左侧项目与会话，中间任务与对话，右侧文件、审查、Git 和用量，底部终端与命令。完整原型为默认入口，规格与对照独立切换。

规格从原来的 11 组核心功能扩展为产品全景、界面架构、16 条完整旅程、保留原锚点的核心规格、全量需求映射、状态与恢复、产品决定与依据。需求映射包含原始验收、依赖、阶段、负责人、设计状态和实现进度，生成时直接读取 backlog，避免第二份手工进度表。

颜色以中性灰为基础：画布 `#202020`、侧栏 `#181818`、输入层 `#2b2b2b`、边界 `#383838`、正文 `#ededeb`、次要正文 `#aaa9a5`。主要动作使用浅色实体按钮，绿色仅标记成功和新增代码，琥珀色用于待决定。去掉旧版渐变、彩色外壳和模拟浏览器地址栏。

界面文字使用本机 Segoe UI Variable / Segoe UI / Microsoft YaHei；代码使用 Cascadia Code / Consolas。主要正文 14 px、次要文字 12 px、新会话标题 30 px。图标统一使用内联 SVG，不依赖图标字体、CDN 或外部字体。

宽屏结构：

```text
外部评审栏：原型 / 规格 / 对照，演示场景，需求进度
┌─ 项目与会话 244 ─┬─ 会话标题、目录与工作面板入口 ────────────┐
│ 新会话 / 搜索   │ 对话与输入                  │ 变更 / 文件 │
│ 已置顶          │ 新会话时输入居中             │ 用量       │
│ 项目及会话      │ 运行时输入位于底部           │ 按需展开    │
│ 最近无项目会话  ├─ 终端 / 后台任务，可收起 ────────────────┤
│ 设置            │ 连接、运行与当前环境状态                   │
└─────────────────┴─────────────────────────────────────────┘
```

窄屏采用可关闭侧栏与工作面板抽屉，保留输入、审批和停止入口；不会通过把三栏都缩小来适配。面板可关闭，右侧宽度可用键盘或指针调整，布局设置保存在原型自己的存储空间。

UI/UX Pro Max 的两次系统查询均返回 FAQ 文档站布局，和本任务的 IDE 工作台不匹配，未采用该布局。颜色、排版与分区按用户指定的 Codex 工作流及通用可用性原则制定；使用其可见焦点、操作反馈、对比度与减弱动效建议。

参考：OpenAI 官方 Projects and chats、Code review、Integrated terminal、Worktrees，以及 Claude Code Desktop application 的任务输入、模式、面板、终端、会话、Worktree 和上下文章节（2026-10-31 实际读取）。终端显式注入、快照回滚、归属 / 目录、无人值守授权仍采用 D01–D15；不复制其他产品的 Bypass、云端执行、订阅权益或不保护改动的清理规则。来源摘要见 `prd-references.md`。

维护：`prd.template.html` 是外壳，`prd-document.html` 是规格正文，`prd-flows.mjs` 是旅程与界面映射，`prd-ui.css` 与 `prd-app.js` 是原型源文件。运行 `node scripts/planning/build-prd.mjs` 生成自包含的 `docs/product/prd.html`。原型使用自己的存储 key，不接触 roadmap 的本地副本，不执行真实命令，也不将设计覆盖升级为产品已实现。

## 第 3–4 轮共同设计（2026-11-01）

用户确认 Codex 式克制、中等密度、按需面板；默认主题跟随系统，明暗两套同等设计，取代旧的暗色默认建议。屏幕原话“1080 100%”，暂按 1920×1080 @100% 制作主稿；窗口习惯尚未提供。完整 PRD 的新默认主题同步为 system，保留用户显式选过的明暗偏好，系统主题变化实时生效。

新增独立的高保真方向评审 `../docs/design/review.html`，使用 `ui-review.css` / `ui-review.js`，不覆盖完整规格。A 对话优先 / B 审查聚焦使用同一任务、相同字号与语义色；支持六场景、主题、明暗对照及核心模拟操作。具体比较、范围与待确认项见 [UI brief](brief.md)。方向待用户选择，不计入实现进度。

## 第 4 轮选择后的核心页面细化（2026-11-01）

用户已确认“组合：A 日常对话 + B 展开审查”和保留当前字号基线（14 / 15 / 12 px）。组合成为新默认预览：打开变更自动进入宽审查，关闭恢复日常对话；A / B 仅作为评审参考保留。旧浏览器评审方向偏好不被当作用户的产品选择；通过 layoutVersion=2 区分新默认，主题偏好继续保留。

高保真入口扩为 18 种状态；创建、停止、同步等依赖服务确认的样本通过外部评审栏推进，不用定时器假装任务结束。补充草稿 / 阅读锚点 / 工具与当前文件的模拟恢复、失效审批、回滚冲突和无快照继续时禁用回滚。具体规则、布局尺寸、覆盖边界和阶段见 [核心页面与状态规格](core-spec.md)。它是已确认方向的细化，完整流程原型保留简化展示，不据此提前验收产品。

## PI-Desktop spec 采纳补充（2026-11-01）

路线由 `../docs/architecture/implementation-plan.md` 确定。沿用上面的配色、字体与布局；不另换视觉系统。M1 即设计 tokens 和基础 UI 壳，M2 交付真实对话，M4 完善布局 / PTY。会话保留消息锚点 / 偏移、工具展开、草稿及面板上下文，初始保留 3 个视图；后台事件不抢焦点或替换文件。流式按帧累计全部 delta，审批 / 错误 / 最终状态立即冲刷；默认本地标题和本地无倒计时审批。

ui-ux-pro-max 两次定向会话阅读位置查询返回平滑锚点与水平溢出建议，未找到匹配的会话恢复规则，不采用为该行为依据。恢复规则参考固定版本 ADR / 源码，键盘 / 焦点 / 响应布局沿用现有设计与通用原则。设计决定不计入产品实现，所有状态仍需 M2 Chromium / Electron 实测。

## R6 默认使用规则（2026-11-01）

用户确认受限只读自动、写文件 / 命令先审批、开发必要真实验收每里程碑最多新增 2 次请求 / 输出 512 token / 失败不自动重试，以及关窗到托盘继续 / 退出应用停止受管任务 / 自启默认关。核心稿新增外观、权限、窗口分类，授权与退出说明可往返，关闭后返回原入口；完整 PRD 权限与恢复同步。开发预算位于评审说明和开发文档，不作为产品用量限制。R7 后续已确认默认应用数据目录可迁移、旧历史首版只读及仅升级前自动备份；R8 确认 Shell / 编辑器、安装更新与后台通知。设计交互不执行真实模型或系统操作。
